# Issue #11: `start` がすべての clone 失敗を新規リポジトリ作成として扱う

> **優先度**: 🟡 中
> **種類**: エラーハンドリング・データ同期 UX
> **対象ファイル**: `src/ai_adapter/cli.py`
> **対象行**: 168-179行目付近

---

## 問題

`ai-adapter start <URL>` は `git clone` の `GitError` を一律に捕捉し、既存設定の取得に
失敗した場合でも「新規リポジトリ」として初期化してセットアップ成功を表示する。

認証失敗、URL の入力ミス、ネットワーク障害、Git サーバー障害を区別していない。

## 影響

- 既存設定を取得できていないのに、ユーザーにはセットアップ成功と見える
- 空のローカル設定を後から push し、リモート設定と競合する可能性がある
- 本当の clone 失敗理由が表示されず、トラブルシュートが困難になる

## 修正方針

- デフォルトでは clone 失敗をユーザー向けエラーとして終了する
- 空のリモートへ新規作成する操作は `--new` 等で明示させる
- 少なくとも Git の失敗理由を表示し、暗黙のフォールバック前に確認する
- 既存の `init --remote` と `start` の責務を整理する

## 受け入れ条件

- [ ] 認証失敗・不正 URL・通信失敗で成功メッセージを表示しない
- [ ] clone のエラー概要と次の操作が表示される
- [ ] 新規リポジトリを作る操作はユーザーが明示的に選択できる
- [ ] 既存リポジトリ取得と新規作成のテストが分離されている
- [ ] `bash scripts/run_tests.sh` が成功する
