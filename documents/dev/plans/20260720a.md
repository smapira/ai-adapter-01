# 開発指示書: ai-adapter — AIエージェント・スクリプト共通管理基盤ツール

## 概要

**ai-adapter** は、CLI で操作する汎用的なスクリプト管理ツール。  
スクリプトをグループ単位で管理し、AIエージェントの指示ファイル（.github/instructions）の切り替え、Git によるバージョン管理を提供する。  
プラグイン機構により機能拡張可能で、一般公開（PyPI）を前提とした設計とする。

### 技術スタック

| 項目 | 採用技術 | 理由 |
|------|---------|------|
| 言語 | Python 3.10+ | 可読性・エコシステムの豊富さ |
| パッケージ管理 | uv | 高速・モダンな Python パッケージマネージャー |
| CLI フレームワーク | Click | プラグイン対応（entry-points）、成熟度、ドキュメントの充実 |
| 設定ファイル | YAML (PyYAML) | 可読性が高く手編集に適す |
| テスト | unittest | 標準ライブラリのみで追加依存不要 |
| プラグイン機構 | Python entry-points (`ai_adapter.plugins`) | setuptools 標準、依存追加不要 |
| Git 連携 | subprocess | 追加依存なし、シンプルな操作のみ |

## フェーズ 1: プロジェクト基盤

### Step 1.1 — プロジェクトスキャフォールディング

**依存**: なし  
**並列**: 不可

以下のディレクトリ構造を作成する。

```
ai-adapter/
├── pyproject.toml              # プロジェクト設定・依存関係
├── README.md                   # プロジェクト説明
├── LICENSE                     # ライセンス（MIT 推奨）
├── .gitignore                  # Git 除外設定
├── src/
│   └── ai_adapter/
│       ├── __init__.py         # バージョン情報
│       ├── __main__.py         # `python -m ai_adapter` 対応
│       ├── cli.py              # CLI エントリーポイント（Click グループ定義）
│       ├── config.py           # 設定ファイル読み書き
│       ├── models.py           # データモデル（dataclass）
│       ├── group.py            # グループ管理ロジック
│       ├── script.py           # スクリプト管理ロジック
│       ├── instructions.py     # .github/instructions 管理
│       ├── git.py              # Git 操作ラッパー
│       └── plugin.py           # プラグイン管理
├── tests/
│   ├── __init__.py
│   ├── test_config.py
│   ├── test_group.py
│   ├── test_script.py
│   ├── test_instructions.py
│   ├── test_git.py
│   └── test_plugin.py
└── examples/
    └── sample-config.yaml      # サンプル設定ファイル
```

**pyproject.toml の設計ポイント:**
- `[project]` セクションで name, version, description, authors, license, readme, requires-python, dependencies を定義
- `[project.scripts]` で `ai-adapter = "ai_adapter.cli:main"` エントリーポイント
- `[project.entry-points."ai_adapter.plugins"]` で空のプラグイン名前空間を定義
- `[build-system]` で `hatchling` または `setuptools` を指定（uv 対応）
- 依存関係は最小限: `click`, `pyyaml` のみ（標準ライブラリでカバーできるものは除外）

### Step 1.2 — データモデル定義 (`src/ai_adapter/models.py`)

**依存**: なし  
**並列**: Step 1.3, 1.4, 1.5 と並列可能

以下の dataclass を定義する:

```python
@dataclass
class Script:
    name: str
    path: Path
    description: str = ""
    tags: list[str] = field(default_factory=list)


@dataclass
class Group:
    name: str
    description: str = ""
    scripts: list[Script] = field(default_factory=list)


@dataclass
class InstructionSet:
    name: str
    path: Path
    description: str = ""


@dataclass
class Config:
    groups: list[Group] = field(default_factory=list)
    current_instructions: str | None = None
    instructions: list[InstructionSet] = field(default_factory=list)
```

YAML とのシリアライズ/デシリアライズメソッドもこのモジュールに実装する。

### Step 1.3 — 設定ファイル管理 (`src/ai_adapter/config.py`)

**依存**: Step 1.2 の models  
**並列**: Step 1.2 と並列可能

- 設定ファイルの探索順序:
  1. カレントディレクトリの `.ai-adapter.yaml`
  2. 親ディレクトリを再帰的に探索（`git rev-parse --show-toplevel` 相当）
  3. 見つからなければ新規作成を促す
- 設定ファイルの読み込み・保存・バリデーション
- デフォルト値の提供

### Step 1.4 — CLI エントリーポイント (`src/ai_adapter/cli.py`)

**依存**: Step 1.3 の config  
**並列**: Step 1.3 と並列可能

Click グループとして以下の CLI 構造を定義（サブコマンドの実装本体は後続フェーズ）:

```
ai-adapter
  ├── init                      # 設定ファイルの初期化
  ├── status                    # 現在の状態表示
  ├── group
  │   ├── list                  # グループ一覧
  │   ├── create <name>         # グループ作成
  │   ├── delete <name>         # グループ削除
  │   ├── rename <old> <new>    # グループ名変更
  │   └── show <name>           # グループ詳細
  ├── script
  │   ├── list [group]          # スクリプト一覧
  │   ├── add <group> <path>    # スクリプト追加
  │   ├── remove <group> <name> # スクリプト削除
  │   ├── run <group> <name>    # スクリプト実行
  │   └── show <group> <name>   # スクリプト詳細
  ├── instructions
  │   ├── list                  # 指示セット一覧
  │   ├── use <name>            # 指示セット切替
  │   ├── show [name]           # 指示セット内容表示
  │   ├── add <path>            # 指示セット追加
  │   └── remove <name>         # 指示セット削除
  └── plugin
      ├── list                  # 有効プラグイン一覧
      └── info <name>           # プラグイン詳細
```

## フェーズ 2: コア機能

### Step 2.1 — `group` コマンド実装 (`src/ai_adapter/group.py`)

**依存**: Step 1.2, 1.3, 1.4  
**並列**: Step 2.2, 2.3 と並列可能

- group list: 全グループの一覧表示（テーブル形式推奨）
- group create: グループの新規作成、重複チェック
- group delete: グループの削除、確認プロンプト
- group rename: グループ名変更、存在チェック
- group show: グループ詳細（スクリプト一覧含む）の表示
- 操作ごとに設定ファイルを更新して保存

### Step 2.2 — `script` コマンド実装 (`src/ai_adapter/script.py`)

**依存**: Step 1.2, 1.3, 1.4  
**並列**: Step 2.1, 2.3 と並列可能

- script list: 全スクリプト一覧（グループ指定でフィルタ可能）
- script add: 既存ファイルのパスをグループに追加（相対パス推奨）
- script remove: グループからスクリプト削除
- script run: スクリプトを `subprocess.run` で実行、終了コード表示
- script show: スクリプトのメタデータ表示
- パスの解決は設定ファイルの場所を基準とする

### Step 2.3 — `instructions` コマンド実装 (`src/ai_adapter/instructions.py`)

**依存**: Step 1.2, 1.3, 1.4  
**並列**: Step 2.1, 2.2 と並列可能

- `.github/instructions/` 配下のファイルを管理
- instructions list: `current_instructions` にマークを付けて一覧表示
- instructions use: 指定した指示セットをアクティブに設定
  - `.github/instructions/current` へのシンボリックリンク or 設定ファイルに記録
- instructions show: ファイル内容を表示
- instructions add: ファイルを `.github/instructions/` にコピーして登録
- instructions remove: 登録解除（ファイルは削除しないオプションも提供）

## フェーズ 3: 基盤機能

### Step 3.1 — `init` / `status` コマンド

**依存**: フェーズ2完了  
**並列**: Step 3.2, 3.3 と並列可能

- `ai-adapter init`: カレントディレクトリに `.ai-adapter.yaml` を生成
  - 対話的に初期設定（グループの作成など）
  - `.github/instructions/` ディレクトリの作成
  - 既存の `.github/instructions` があれば自動検出して登録
- `ai-adapter status`: 現在の設定状態を表示
  - 有効なグループ数、スクリプト数、アクティブな指示セット

### Step 3.2 — Git 連携 (`src/ai_adapter/git.py`)

**依存**: なし  
**並列**: Step 3.1, 3.3 と並列可能

- `git init` のラップ（任意）
- `git add`, `git commit` の簡易ラップ
- `.gitignore` へのエントリ追加（必要に応じて）
- Git がインストールされているか確認

### Step 3.3 — プラグイン機構 (`src/ai_adapter/plugin.py`)

**依存**: なし  
**並列**: Step 3.1, 3.2 と並列可能

- `importlib.metadata.entry_points` を使用して `ai_adapter.plugins` グループのエントリーポイントを検出
- プラグインは Click のグループにサブコマンドを追加可能
- plugin list: ロード済みプラグイン一覧
- plugin info: プラグインのメタデータ表示
- プラグインインターフェースの設計:
  ```python
  @dataclass
  class PluginInterface:
      name: str
      version: str
      description: str
      commands: list[click.Command]  # 追加するCLIコマンド
  ```

## アーキテクチャ上の重要ポイント

1. **プラグイン設計**: `ai_adapter.plugins` entry-points グループで発見。各プラグインは Click の `Group` または `Command` を提供する。プラグインが独自の設定セクションを持てるようにする。

2. **設定ファイル設計**:
   ```yaml
   # .ai-adapter.yaml
   version: 1
   groups:
     - name: deploy
       description: デプロイ関連スクリプト
       scripts:
         - name: deploy-prod
           path: scripts/deploy-prod.sh
           description: 本番デプロイ
         - name: deploy-staging
           path: scripts/deploy-staging.sh
           description: ステージングデプロイ
   instructions:
     current: code-assist
     items:
       - name: code-assist
         path: .github/instructions/code-assist.md
         description: コーディングアシスト用指示
       - name: review
         path: .github/instructions/review.md
         description: コードレビュー用指示
   plugins: {}
   ```

3. **エラーハンドリング**: 全 operation で統一されたエラーメッセージ。`click.ClickException` を継承し、終了コードを一貫させる。

4. **プラグイン非依存**: コア機能はプラグインなしで完結する。プラグインはあくまで拡張ポイント。

## 検証手順

1. **ユニットテスト**: `uv run python -m unittest tests/test_*.py` が全件 PASS
2. **CLI テスト**:
   - `ai-adapter init` で設定ファイルが生成される
   - `ai-adapter group create test-group` でグループ作成
   - `ai-adapter script add test-group /path/to/script.sh` でスクリプト追加
   - `ai-adapter script run test-group script.sh` でスクリプト実行
   - `ai-adapter instructions list` で指示セット一覧表示
3. **プラグインテスト**: テスト用プラグインを登録して plugin list に表示される
4. **エラーケーステスト**: 存在しないグループの削除、重複作成などが適切にエラーを返す
5. **README の手順通りに操作できること**
