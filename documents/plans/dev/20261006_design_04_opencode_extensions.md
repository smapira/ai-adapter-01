## 1. 目的

OpenCode provider の既存実装（alias / install / validate）を拡張し、
User スコープと jsonc、互換 skills パスをカバーする。

### 対象ギャップ

| 12 | `~/.config/opencode/agents/<name>.md` | ❌ |

## 2. アプローチ

### 2.1 jsonc 対応

`opencode.jsonc` は JSONC（コメント付き JSON）。
現在の `_load_json_file` は `json.load` のみ使用。

**方針**: 読み取り時にコメントを除去してからパースする。

```python
def _strip_json_comments(text: str) -> str:
    """Remove // and /* */ comments from JSONC text."""
    # 行コメント + ブロックコメントを除去（文字列内は考慮）

def _load_json_file(path: Path) -> dict | list[str]:
    # .jsonc 拡張子の場合、コメント除去後に json.loads
```

**CLI 影響**:
- `opencode install` は従来どおり `opencode.json` を生成
- `opencode validate` は `.json` / `.jsonc` の両方を検証
- `opencode install --format jsonc`（新規）で `opencode.jsonc` を生成

### 2.2 User スコープ deploy

`~/.config/opencode/` 配下へのデプロイを追加する。

```bash
# agents
ai-adapter sub-agent get <name> --format opencode --scope user
# → ~/.config/opencode/agents/<name>.md

# commands
ai-adapter command get <name> --format opencode --scope user
# → ~/.config/opencode/commands/<name>.md
```

**既存プロジェクトデプロイは変更しない**:
- `opencode alias` → `.opencode` → `.github` symlink（現状維持）
- `opencode install` → プロジェクト `opencode.json` 生成（現状維持）

### 2.3 互換 skills パス

OpenCode は `.claude/skills/` と `.agents/skills/` も探索する（互換）。
現在は `opencode.json` の `skills.paths` が `.github/skills` のみ。

**方針**: `skills.paths` に互換パスを追加できるようにする。

```bash
ai-adapter opencode install --with-compat-skills
# → opencode.json の skills.paths に以下を追加
#   ".github/skills",
#   ".claude/skills",
#   ".agents/skills"
```

**デフォルトは現状維持**（`.github/skills` のみ）。
`--with-compat-skills` オプションで明示的に追加。

### 2.4 `~/.config/opencode/opencode.json` の scan → manage

現在は scan のみ。本設計書では **scan は維持し、manage はしない**
（User config の書き換えはリスクが高いため）。

将来的に `opencode install --user` で User config の MCP セクションを
マージする機能を追加する可能性があるが、本設計書のスコープ外。

## 3. BDD タスク分解

### タスク 04-1: jsonc 読み取り対応

**期待する振る舞い**:
- 入力: `opencode validate`（`opencode.jsonc` にコメント付き JSON が存在）
- 応答: コメントを除去してパースし、検証結果を表示
- 入力: `opencode.jsonc` のみ存在（`opencode.json` なし）
- 応答: **valid と判定**（"opencode.json not found" エラーにしない）
- 入力: `opencode.jsonc` に構文エラー
- 応答: エラーメッセージ（コメント除去後もパース失敗）

**受け入れ条件**:
- AC1: `//` 行コメントと `/* */` ブロックコメントを除去
- AC2: 文字列内の `//` はコメントと見なさない
- AC3: `opencode.json`（コメントなし）の動作は変更なし
- AC4: 検証対象ファイルの探索順序: `opencode.json` → `opencode.jsonc`
- AC5: **`opencode.jsonc` 単独でも valid（not found エラーにしない）**

**データ（仕様例）**:
```jsonc
// OpenCode configuration
{
  "lsp": false,
  /* permissions */
  "instructions": [".github/copilot-instructions.md"]
}
```

---

### タスク 04-2: `opencode install --format jsonc`

**期待する振る舞い**:
- 入力: `ai-adapter opencode install --format jsonc`
- 応答: `opencode.jsonc` を生成（JSONC 形式、コメント付き）
- 入力: `opencode.json` が既に存在
- 応答: 確認プロンプト後、`opencode.jsonc` を生成（`.json` は残す）

**受け入れ条件**:
- AC1: 生成される jsonc には説明コメントが含まれる
- AC2: `--format` 省略時は従来どおり `opencode.json`
- AC3: uninstall は両方の拡張子を対象

**データ（仕様例）**:
```jsonc
// Generated by ai-adapter opencode install
// Schema: https://opencode.ai/config.json
{
  "$schema": "https://opencode.ai/config.json",
  "lsp": false,
  "instructions": [".github/copilot-instructions.md"],
  "mcp": { "servers": { ... } },
  "skills": { "paths": [".github/skills"] }
}
```

### タスク 04-3: `sub-agent get --format opencode --scope user`

**期待する振る舞い**:
- 入力: `ai-adapter sub-agent get <name> --format opencode --scope user`
- 応答: `~/.config/opencode/agents/<name>.md` に配置
- 入力: `~/.config/opencode/agents/` が存在しない
- 応答: ディレクトリを作成して配置

**受け入れ条件**:
- AC1: frontmatter は保持（OpenCode は Markdown+YAML）
- AC2: `--scope project`（デフォルト）は既存 `.github/agents/` へのデプロイ
- AC3: **`.agent.md` → `.md` リネームは行わない**（OpenCode は拡張子非依存で探索する前提。**要仕様確認**）
  - 実装前に OpenCode の agents ディレクトリ探索規則を確認する
  - `.md` 正規化が必要と判明した場合は Claude Code（設計書 02）と同じリネームを行う
- AC4: `--scope` は設計書 01 の `resolve_scope_path()` を再利用（独自実装しない）

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| jsonc パーサのエッジケース | 正規表現ではなく簡易トークナイザを使用。テストケースを十分用意 |
| User config への誤書き込み | 本設計書では User config の **write はしない**（scan のみ維持） |
| compat-skills によるパス重複 | validate で重複パスを警告 |
| jsonc 生成時のコメント挿入 | `json.dumps` ではコメントを出せないため、コメント挿入用の小さな出力ヘルパーが必要（実装は容易） |
| compat-skills の参照パス未整備 | `.claude/skills` / `.agents/skills` は 02/03 実装前は未存在の期間があるが、パス未存在でも OpenCode はスキップするため害は無い |
